# 批量混剪（Python + FFmpeg）

把多个“分镜文件夹”按固定顺序（A → B → C → …）各随机抽一条素材拼成一条成品，批量生成，组合不重复，速度优先。

---

## 1. 设计思路

### 组合去重：编号法
- 每个组合看成一个**混合进制整数**：第 k 个文件夹有 nₖ 条素材，选中第 iₖ 条，编号 = i₀·(n₁n₂…) + i₁·(n₂…) + … 。总组合数 = n₀×n₁×…×nₖ。
- “抽 N 个不重复组合”就变成“从 0 ~ 总数-1 里抽 N 个不重复整数”：用 `random.sample(range(总数), N)` 一次抽完，再把编号拆回每个文件夹的素材序号。对 `range` 抽样不会生成大列表，几百万、几亿种组合都是瞬间完成，100% 不重复。组合数大于 2⁶³ 时自动改用 Floyd 抽样，同样严格不重复。
- **跨批次去重**：已生成的组合按“文件名”记在历史文件里（按文件夹列表区分项目）。下次先把历史换算成编号，从“剩余编号”里按名次抽样，再映射回真实编号，自动跳过用过的，不需要“撞了重抽”。
- **使用次数均衡**：先抽 4 倍的候选组合，再用“分级配额”从中挑：每个素材有使用上限，从低往高逐级放开，少用的素材先入选。实测 4 个文件夹各 10 条、生成 100 条，每条素材的使用次数在 8~11 次之间（纯随机是 2~19 次）。
- 每批导出 CSV，记录每条成品用了哪些素材。

### 速度：规格一致就直接拼接，不一致才预处理
0. **直接拼接（默认开启，最快）**：以这批素材里**多数**的规格为准（编码、分辨率、帧率、像素格式、时间基、音频参数），规格相同的素材直接复制拼接原文件，不转码；只有少数不一样的才处理：
   - 只有音频不同、没有音轨、或时间基不同 → 只重新封装（画面不重新编码，几乎不花时间）
   - 分辨率或帧率不同 → 只把这几条转成多数素材的规格
   - 需要转码的超过 60% → 自动改走下面的“统一转码”流程
   实测：帧率或时间基不同的文件直接拼会出现时间戳倒退（播放卡顿），所以这两项也必须一致。日志会列出每种规格各有多少条。
1. **只预处理用得到的素材**：先规划好这批组合，再只转码其中用到的素材（比如 6 个文件夹共 379 条素材，生成 50 条通常只需处理约 180 条）；以后的批次用到新素材再按需补转。
2. **预处理 + 缓存**：所有素材统一转成同一套规格：H.264、同分辨率（缩放后补黑边，不拉伸）、同帧率、yuv420p、MPEG-TS 90kHz 时间基，音频 44100Hz 双声道。按“路径 + 大小 + 修改时间”判断，处理过的直接用。
3. **拼接时视频绝不重新编码**：用 concat demuxer 直接复制 H.264 数据流，速度只取决于硬盘读写。
4. **缓存一致性**：缓存目录按“编码参数指纹”区分。改了分辨率、帧率、编码器或画质，旧缓存会自动作废并删除，不可能混拼。
5. **“规格一致就跳过转码”从严判断**：除了编码、分辨率、帧率、像素格式等参数，还要求 H.264 的 SPS/PPS 指纹和本程序编码出来的完全一致（防止拼接花屏），并且是整数帧。拿不准就统一转码。

### 其它提速与开关
- **按需检查素材**：先排好这批的组合，只检查用得到的素材的规格（结果会记住，下次不再检查）。
- **成品只写一遍硬盘**：成品文件开头预留好索引的位置，写完数据直接填入，仍然支持“边下边播”，不用像传统 faststart 那样把整个文件再搬一遍。预留不够时自动退回传统做法。
- **强制直接拼接**（默认关闭）：完全不转换素材。规格和多数不一样的素材会在日志里列出，用到它们的成品可能花屏、卡顿或音画不同步，需要自己检查。
- **换公式自动清理缓存**（默认开启）：分镜文件夹和上一次不一样时，开始前自动清空缓存；只调整顺序不算换公式。

### 防音画不同步（实测发现并修正的问题）
AAC 音频以 1024 个采样为一帧，还带编码器延迟，所以每段音频都会比视频长 30~40ms。如果缓存里直接存 AAC，多段拼接后视频每个接缝都会多出几十毫秒的停顿。

所以缓存里每条素材存两个文件：
- `.ts`：只有视频，帧数 = round(时长 × 帧率)
- `.wav`：PCM 音频，采样数精确等于视频时长（短了补静音，长了裁掉）

拼接时视频流直接复制，音频拼好后编一次 AAC。音频编码很轻，换来的是每一段都音画严格对齐。这是在“拼接阶段绝不重新编码”这条要求上做的有意取舍：**视频完全不重编码，只有音频编码一次**。

## 2. 文件结构

```
BatchMixCut/
├─ main.py              程序入口（图形界面）
├─ cli.py               命令行版本（可选）
├─ 双击运行.bat         第一次：自动安装环境 + 建桌面快捷方式；之后：直接打开
├─ 打包exe.bat          一键打包成 exe（可选）
├─ tools/               上面两个 bat 调用的安装 / 打包脚本
├─ requirements.txt
├─ ffmpeg/              ffmpeg.exe、ffprobe.exe（双击运行时自动下载）
├─ mixcut/
│  ├─ gui.py            界面（PySide6）
│  ├─ engine.py         任务调度：扫描→探测→预处理→规划→并行拼接
│  ├─ combo.py          组合算法（编号法 / 跨批次 / 均衡）
│  ├─ history.py        历史记录
│  ├─ preprocess.py     预处理与缓存
│  ├─ concat.py         FFmpeg 拼接（极速 / 慢速转场）
│  ├─ ffmpeg_tools.py   FFmpeg 调用、探测、硬件编码检测
│  └─ utils.py          自然排序、路径等
└─ tests/               自测脚本（生成测试素材 + 校验成品）
```

程序运行后会在程序目录下生成 `data/` 文件夹，里面是缓存、历史记录和配置。如果程序目录没有写入权限，会改放到 `%LOCALAPPDATA%\BatchMixCut`。

## 3. 安装 FFmpeg（双击运行.bat 会自动下载，下面是手动方法）

1. 打开 <https://www.gyan.dev/ffmpeg/builds/>，下载 **ffmpeg-release-essentials.zip**（也可以用 <https://github.com/BtbN/FFmpeg-Builds/releases> 的 `ffmpeg-master-latest-win64-gpl.zip`）。
2. 解压后进入 `bin` 文件夹，把 **ffmpeg.exe** 和 **ffprobe.exe** 复制到本程序的 `ffmpeg` 文件夹里。
3. 也可以把 ffmpeg 加到系统 PATH，程序会自动找到。

这两个版本都自带 NVIDIA（h264_nvenc）、AMD（h264_amf）、Intel（h264_qsv）硬件编码。程序会实际试编一小段来确认能用，不能用就退回 CPU。

## 4. 新手运行步骤（双击即可）

1. 把压缩包**解压**到一个固定位置，比如 `D:\批量混剪`（不要在压缩包里直接运行）。
2. 双击 **`双击运行.bat`**。如果 Windows 弹出安全提示，选“仍要运行”/“运行”。
3. 第一次会自动完成下面这些事，期间会看到一个黑色窗口显示进度，大约需要 3~10 分钟（视网速）：
   - 没有 Python 就自动安装 Python 3.12（只装给当前用户，不需要管理员权限）
   - 在程序文件夹里创建独立运行环境 `.venv`，不影响电脑上其它 Python
   - 安装界面组件 PySide6（官方源失败会自动改用国内镜像）
   - 自动下载 ffmpeg 到 `ffmpeg` 文件夹（已经装过 ffmpeg 的话会直接用）
   - 在**桌面创建“批量混剪”快捷方式**
   - 打开程序
4. **以后直接双击桌面上的“批量混剪”**就能打开，没有黑色窗口。（再双击 `双击运行.bat` 也可以，会先快速检查一遍再打开。）
5. 在界面里操作：
   - 左边点“从父文件夹导入子文件夹”，选中装着各个分镜文件夹的那个大文件夹，会自动按名称自然排序（`新建文件夹`、`新建文件夹 (2)` … `新建文件夹 (10)`）。也可以一个个添加，或者直接把文件夹拖进窗口。顺序可以用“上移 / 下移”调整。
   - 右边设置生成数量，看一下“组合数”：最多多少种、历史用了多少、还剩多少。
   - 底部选输出路径，点 **开始处理**。
6. 第一次生成会先预处理（统一转码），之后每次都直接用缓存，只剩拼接。

> 程序出错时会弹窗提示，详细信息保存在 `data\error.log`，把这个文件发给开发者即可。
>
> 如果自动安装失败（比如公司电脑禁止安装软件），按旧方法手动装：装 Python（勾选 “Add python.exe to PATH”）→ 在本文件夹执行 `pip install -r requirements.txt` → 把 ffmpeg.exe、ffprobe.exe 放进 `ffmpeg` 文件夹 → `python main.py`。

### 参数建议
| 参数 | 建议 |
|---|---|
| 分辨率 | 默认“以第一条素材为准”；做抖音可以直接选 1080×1920 |
| 帧率 | 30 |
| 编码器 | 自动检测。显卡编码明显快于 CPU，只影响预处理阶段。检测失败时日志会写明原因（最常见是显卡驱动太旧） |
| 画质 | 20（18~23 常用，越小越清晰、越大） |
| 转码速度 | 标准。用 CPU 转码嫌慢可选“更快”：约快一倍，但文件约大一倍 |
| 预处理并行数 | CPU 编码 2；显卡编码 2~3 |
| 拼接并行数 | 机械硬盘 2~4，固态硬盘 4~8 |
| 模式 | 极速模式。慢速模式（转场）每条都要完整重新编码 |

## 5. 命令行用法（可选）

```
python cli.py --parent "D:\素材\项目A" --out "D:\成品" --count 800
python cli.py --folders "D:\A" "D:\B" "D:\C" --out "D:\成品" --count 100 --encoder h264_amf
python cli.py --help
```
`--on-exceed remaining|repeat|cancel` 用来指定数量超过剩余组合时怎么处理。

## 6. 打包成 exe（可选）

先双击运行过一次 `双击运行.bat`，再双击 **`打包exe.bat`**。它会安装 PyInstaller，然后执行：

```
pyinstaller --noconfirm --clean --onedir --windowed --name BatchMixCut ^
  --add-binary "ffmpeg\ffmpeg.exe;ffmpeg" ^
  --add-binary "ffmpeg\ffprobe.exe;ffmpeg" ^
  main.py
```

打包结果是 `dist\BatchMixCut\` 整个文件夹，里面的 `BatchMixCut.exe` 双击就能用，ffmpeg 已经打包进去了，拷到别的电脑也不用再装 Python 和 ffmpeg。

推荐用 `--onedir`（文件夹形式）。如果一定要单个 exe，把 `--onedir` 换成 `--onefile`；但每次启动都要先把一百多 MB 的 ffmpeg 解压到临时目录，启动会慢几秒，也更容易被杀毒软件误报。

## 7. 常见问题

- **成品花屏 / 拼接报错**：先点“清理缓存”再生成。正常情况下缓存参数指纹会自动保证一致。
- **某些素材被跳过**：日志会写明原因（损坏、没有视频轨、无法确定时长等）。其它素材照常处理，不影响整批任务。
- **想要同样的组合再来一遍**：点“清空历史”。
- **停止处理**：已经完成的成品、CSV 和历史记录都会保留，未完成的临时文件会自动删除。
- **磁盘空间**：开始拼接前会检查输出盘剩余空间，不够会提示。缓存占用显示在界面上，可以随时清理。

## 8. 自测（开发者）

`tests/` 里有两个脚本，需要 ffmpeg 在 PATH 中：
```
python tests/make_samples.py "D:\测试\素材"           # 生成 3 个文件夹 × 3 条不同分辨率/帧率/格式的素材
python cli.py --parent "D:\测试\素材" --out "D:\测试\成品" --count 10
python tests/verify.py "D:\测试\成品" "D:\测试\成品\混剪_清单_xxx.csv"
```
每条测试素材在第 1 秒有一帧白闪，同时有一声“哔”。校验脚本逐帧检查顺序、片段位置和音画偏差。
